# v0.8.1 — Startup recovery and duplicate-power fix

- Fix power deduplication for real multipart installation unique IDs. Match configuration entry ownership instead of comparing differently split identifier strings. The regression fixture now uses a multipart URL/project/site identity.
- Give the heating-curve module a fresh per-boot cache key, stable across retries within a boot. Register its HTTP routes before publishing the URL to the frontend and Lovelace resources. This lets a client retry an import that failed while the integration's HTTP handler was not ready. Old module routes remain available.
- Attempt backed-up dashboard upgrades 15 seconds after Cascade platform setup, in addition to the existing HA-started callback. Unrelated slow integrations no longer hold the first attempt until the entire system finishes starting. The early callback is cancelled when the entry unloads.
- Add boot-key and early-refresh checks and browser recovery from an initial 404; retain 122 Python tests and Chromium/WebKit interaction checks.

Update through HACS, restart Home Assistant and reload the client. Recognized generated dashboards upgrade automatically. Other supported generated layouts can use `panasonic_cascade.populate_dashboard` with `update: true`; avoid replacement when retaining custom cards.

This update changes presentation and module delivery, not heat pump settings. Missing measurements remain missing; calculated COP and the distinction between kW power and kWh energy are unchanged from 0.8.0.
