Daily starts, clearer dashboards, and the heating-curve HTTP startup fix.

- Added one **Starts today** sensor per heat pump, counting recorded off → on transitions since local midnight. Counts are reconstructed from Recorder after restarts and refreshed approximately every minute. An initial on state, a run spanning midnight, or an on sample following an unknown gap does not create an inferred start. `partial_day` identifies incomplete coverage. Missing/excluded Recorder history produces unavailable, not zero.
- Shortened default entity/device/dashboard labels, for example **WP 2 · Kühlen/WRG · el. Leistung**, **WP 1 · Heizen · Stromzähler**, and **WP 1 · Verdichterstunden**. Existing unique IDs and entity IDs remain stable; user-assigned entity names remain under Home Assistant's control.
- Removed the four duplicate heating-curve controls from the general Controls card when the editable curve card exists. Other controls remain.
- Removed the legacy unknown Site Info energy placeholders from generated energy overview cards and charts. Real per-unit kWh counters remain, including legitimate zeros. Full values and diagnostics remain under All values. Actual compressor-hour counters are preferred over repeated plant min/max diagnostics in the runtime overview.
- Fixed the confirmed HTTP 404 cause: frontend initialization previously gated static file registration. HTTP is now an explicit dependency, the card file is registered independently of frontend readiness, and missing module/resource registration is retried after HA starts. A real HA HTTP test verifies status 200 and JavaScript content at both legacy and versioned URLs before the frontend is initialized.
- Changed the module URL to `/panasonic_cascade/heating-curve-0.7.0.js?v=0.7.0`, retaining `/panasonic_cascade/heating-curve.js` as an alias. Old resource entries are migrated automatically.
- Added daily-count, label, overview cleanup, actual HTTP and delayed-startup tests, bringing the Python suite to 110 tests. Frontend interaction/responsive checks cover Chromium and WebKit.

Update to 0.7.0 in HACS, restart Home Assistant, reload the browser/app, then apply the dashboard improvements without replacing existing cards:

```yaml
action: panasonic_cascade.populate_dashboard
data:
  url_path: panasonic-cascade
  update: true
```

Use your dashboard's actual URL path. Safe update adds the new daily-count card, shortens matching generated labels and removes only recognized redundant/placeholder rows in the relevant integration cards. Existing custom cards and settings are retained and the previous configuration is backed up first.

Starts today are observed changes in the controller's running-state entity, not a hardware-provided lifetime compressor-start counter. Polling and recording gaps can miss physical events. The integration does not recreate missing historical samples, invent energy readings, or change heat pump settings during an update. Prior hardware-write and phone-delivery limits remain unchanged.
