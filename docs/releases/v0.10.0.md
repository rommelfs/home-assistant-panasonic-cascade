# v0.10.0 — Reliable curve loading and 200 W cycling estimates

## Heating curve

The previous integration published the same module as an early frontend extra module and a Lovelace resource. Early execution can precede Home Assistant's scoped custom-element registry, losing the registration while the evaluated module remains cached. This matches [the upstream frontend race report](https://github.com/home-assistant/frontend/issues/53890). The early import was present in the reference installation's served index document.

Storage-mode dashboards now use only the awaited Lovelace resource. The module waits for HA's root element in the current registry before declaring/registering its card class, including YAML fallback and cached index documents. A new 0.10.0 filename avoids old module-cache entries; legacy paths remain served. Other scripts and YAML resources are preserved.

## Cycling

- Use explicit per-unit total electrical power: **on at/above 200 W, off below 200 W**. Configure the threshold in the integration options (50–5000 W).
- Add a clearly labeled power-derived binary on/off band, migrating recognized controller-enable bands while preserving their history range.
- Reconstruct absolute daily crossing counts for today and the preceding six local calendar days from retained numeric power history. Normalize W/kW per sample, preserve gaps, and avoid counting initial high samples, high samples after gaps, or restarts as starts.
- Keep existing daily-counter IDs. Mark incomplete days and missing history; retain raw power. Recalculate on threshold change. Cache closed days to avoid repeatedly reading a full week.
- This is an estimated compressor activity measure: auxiliary loads can cross the threshold and phases shorter than the polling interval can be missed. The controller enable flag is not used. No controller writes are involved.

Validation: Python tests cover units, the exact threshold, invalid samples, gaps, Recorder restart reconstruction, day boundaries and timeline migration. Chromium/WebKit checks include cold-load registry replacement at four timings and concurrent imports, alongside curve editing, preview/write separation and responsive layout.

Update through HACS, restart Home Assistant and fully reload the client once. Recognized storage dashboards update with a backup. Daily tables can use existing retained power history; the new binary band starts collecting after installation. Hardware-control and phone-notification limitations remain unchanged.
