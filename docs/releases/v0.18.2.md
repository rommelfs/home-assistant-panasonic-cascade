# v0.18.2 — PV, battery, then measured grid

Adds an opt-in **WP-priority** allocation policy for a shared grid measurement including the heat pumps. Remaining local PV is attributed first, then measured battery discharge, then actual grid import. Export and battery charging are excluded from available supply. Grid attribution is never invented to cover a mismatch between Panasonic-reported WP demand and actual supply: any unexplained residual stays unassigned and is shown in the overview and source attributes.

This is a labelled priority accounting convention, not direct provenance metering. Other household loads can share the same sources; absolute attribution remains an estimate, especially when controller power exceeds physical supply. A dedicated WP power meter is needed for precise consumption. Existing proportional and inner-house-branch cascade modes are unchanged. Priority requires a shared measurement boundary and gets an isolated ledger/entity series so earlier assumptions are not relabelled.

Battery minimum SOC remains controlled by the battery/inverter. The integration follows measured discharge and actual grid import, not a hardcoded 8% threshold. No heating, charging or battery commands are added.

Regression cases include 3,070 W reported WP / 2,595 W battery / 10 W grid: 2,595 W battery, 10 W grid and 465 W explicitly unassigned; battery cutoff, source ordering, export, grid charging, invalid telemetry, policy-ledger isolation and rendered dashboard warnings are also covered.
