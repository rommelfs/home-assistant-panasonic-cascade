New alarm push destination option: select an existing Companion App notification target. On iPhone, delivery uses the Home Assistant Companion App and its push infrastructure, including Apple APNs. Home Assistant may prefer local push when available. Time-sensitive iPhone/iPad notifications are separately configurable.

With a destination selected, an additional read-only request checks active alarms approximately every five seconds. Each new alarm episode is handed to the phone once, with a marker retained across ordinary restarts. A new alarm timestamp or an observed normal state allows a subsequent notification. Enabling the feature also reports already-active alarms that have not been sent. The domestic-hot-water visibility option remains effective.

The integration's device page includes an alarm push test button. It sends an explicitly identified test message without creating a controller alarm.

Setup:

1. Update to 0.5.0 in HACS, enabling prereleases if necessary, and restart Home Assistant.
2. Connect the Companion App on the iPhone to Home Assistant and allow notifications.
3. Open the integration's configuration, select your phone as the alarm push destination, and save. Optionally enable time-sensitive notifications here and allow them in iOS.
4. Press the device's alarm push test button and confirm receipt on the phone.

Selecting the disabled/empty destination turns off notifications and the additional fast checks. Notifications are disabled by default for existing entries. Normal measurements retain their previous polling interval.

Five seconds is a check interval, not a guaranteed end-to-end delivery time. Controller response and push delivery take additional time; very short alarms between checks can be missed. Actual display depends on connectivity and phone permissions. A successful Home Assistant action confirms handoff to the notification integration, not receipt on the phone.
