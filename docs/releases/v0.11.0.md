# v0.11.0 — Temporary PV buffer charging and charge history

Add an opt-in buffer offset and a temporary PV charge controller. The original offset is persisted before any change and restored on stop, expiry, guard failure or integration restart/reload. Failed restoration stays pending and retries after reconnect. A changed external default is preserved and produces a conflict notification; higher-priority schedules are left untouched when restoring the original default.

- Configure signed grid/battery power, PV production and actual buffer temperature sources. Unknown/stale measurements, grid import, battery discharge, no PV production, non-heating mode and the temperature limit block or end charging.
- Default policy: 1500 W export start, 500 W stop, 120 seconds stable export, 60 seconds maximum measurement age, 5 °C offset and 30 minutes maximum duration. Automatic start and charging itself are disabled until explicitly configured and verified.
- The captured controller offset supports **0–10 °C** only. A configurable temperature stop limit up to **75 °C** does not set a 75 °C buffer target. No heating-curve, zone-enable or SG Ready changes are made.
- Use the start/stop buttons or `panasonic_cascade.start_buffer_charge` / `stop_buffer_charge`. Overlapping starts cannot replace or extend a charge. A persistent manual offset remains separately identified as **Puffer · Zonenversatz (dauerhaft)**.
- Prominent WP overview cards display confirmed active charging, remaining time and restoration problems. Add a 24-hour on/off charge-permission band and a seven-day history view with associated buffer/PV/grid/battery plots. Unknown in the band means controller effect/restoration is uncertain; this is not a compressor-running signal.
- Preserve existing entity identities and energy/runtime/custom dashboard cards. Recognized generated dashboards receive backed-up additive upgrades. Other dashboards can use `populate_dashboard` with `update: true`.

Validation: **184 Python tests**, five frontend logic tests and a real local HA lifecycle/service smoke test with a simulated controller. The smoke test applies an offset from 2 to 7 °C, persists the original value, reloads the integration and verifies restoration to 2 °C without resuming charging. Hardware writes and hydraulic commissioning have not been performed.

Install through HACS, restart HA, and select **Configure → Configure temporary PV buffer charging**. Verify the measurement signs, hottest-point buffer sensor, permitted temperature and mixing circuit before enabling it. See [operation and restoration details](../pv-buffer-charge.md). Software cannot restore a persistent controller default while HA or controller communication is unavailable; do not remove/disable the integration with restoration pending.
