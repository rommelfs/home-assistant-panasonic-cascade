# v0.7.1 — Daily cycling counts you can read

- Added a native **Einschaltungen pro Tag** (starts per day) table: Today, Yesterday and five earlier dates, with a separate column for each heat pump.
- Reconstruct seven local calendar days from Recorder in one query per heat pump. Existing Starts today entity IDs and numeric states remain unchanged; the `daily_starts` attribute adds the dated counts.
- Automatically insert the table after startup into recognized integration runtime views in storage dashboards. Save a configuration backup before each change, preserve existing graphs/cards/settings, and avoid duplicate tables. Custom tables, panel views and unrelated dashboards are left intact.
- Missing history is displayed as a dash; an asterisk marks incomplete coverage. Entirely unknown history no longer produces a misleading zero. Local midnight, restart and daylight-saving boundaries are covered.
- Added actual Home Assistant template-rendering and safe dashboard-upgrade checks. The Python suite contains 116 passing tests; frontend checks cover Chromium and WebKit.

Update to **0.7.1** in HACS and restart Home Assistant. In a recognized existing **Runtime & cycling** view the table is added automatically. Other supported generated layouts can be updated without replacement:

```yaml
action: panasonic_cascade.populate_dashboard
data:
  url_path: your-dashboard-path
  update: true
```

Counts are confirmed recorded off → on transitions of the controller's running-state entity, not a hardware lifetime compressor-start register. Controller polling and recording gaps can miss physical events. Missing past samples cannot be recovered by installing this update. No heat pump settings are changed. The heating-curve module remains at its unchanged 0.7.0 URL. Hardware-write and phone-delivery limitations remain unchanged.
