Repair missing on/off sensors and the heating-curve frontend.

- Fixed an undefined `row` variable in binary sensor initialization. A normal Boolean point could raise a NameError before the platform added its entities, leaving running-state entities absent and preventing the native cycling timeline from displaying data.
- Kept the native 24-hour history card as a simple horizontal running/stopped band per heat pump. It uses actual running-state entities and retains their unique IDs; it does not derive runtime from an enable command.
- Moved frontend registration before controller refresh and platform setup so it is independent of controller/platform failures.
- Added the bundled heating-curve module to real Lovelace storage resources. Existing integration URLs are migrated to `/panasonic_cascade/heating-curve.js?v=0.6.2`; duplicates are removed, unrelated resources are preserved, and YAML resource collections are left unchanged. A resource storage error is logged without blocking sensor setup.
- Retained all four heating-curve inputs: maximum/minimum water and outdoor temperature, immediate local curve preview, and explicit Apply.
- Added five regression tests covering complete binary platform setup, running-state changes, the binary-only native timeline, early startup ordering, and real resource storage creation/migration/YAML behavior. The Python suite now contains 100 tests.

Update to 0.6.2 in HACS, restart Home Assistant, then fully reload the browser or Companion App. Existing cards do not need to be replaced. If a desired card was never added, use `panasonic_cascade.populate_dashboard` with `update: true` to add missing content while preserving existing cards.

Sensor timelines require recorded running-state samples; missing past samples cannot be reconstructed. Energy/runtime/dashboard backup behavior from 0.6.1 is retained.
