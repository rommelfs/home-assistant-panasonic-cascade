# v0.9.0 — Short fields, fewer controls and honest cycling status

- Use card context instead of controller paths: concise measurement labels in generated live lists and graphs, such as WP 1 Heizen · Strom, WP 2 · Vorlauf, or Vorlauf within a WP 2 group. Shorten and consolidate generated detail groups.
- Keep the overview focused on Zone 1 enable, operating mode and quiet mode. Put additional setpoints, combined-zone controls and SG Ready in a separate Settings view. Keep All values read-only; do not duplicate editable curve inputs there.
- Set display precision: temperature and kWh one decimal, kW/COP two, W/runtime hours whole numbers. Preserve raw numeric states and recording precision.
- Correct the meaning of equipment isRunning: live verification showed it remains enabled across apparent idle periods. Rename it Betriebsfreigabe (operating enable), with a correspondingly named history band. It is not a confirmed compressor-running signal.
- Stop counting this flag as compressor starts. No verified compressor-status model is currently allowlisted. Existing counter IDs remain, but return unavailable with a reason; the dashboard explains the missing signal instead of displaying false zero counts. No power threshold, estimate or inferred physical start is used. Earlier operating-enable counts are not compressor counts.
- Preserve custom cards, history ranges, energy diagrams and existing unique IDs during backed-up generated-dashboard updates. The 0.8.1 per-boot curve resource is unchanged.

Validation: 127 Python tests, including context labels, precision without raw-value rounding, read-only details/separate settings, and rejection of operating-enable as a compressor source; Chromium/WebKit interaction and module-recovery checks.

Update via HACS, restart HA and reload the client after the integration has loaded. Recognized generated dashboards update automatically; safe manual updates remain available with populate_dashboard and update: true. Hardware-control and phone-delivery limitations still apply.
