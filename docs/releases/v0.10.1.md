# v0.10.1 — Automatic reconnection after controller restarts

Controller username/password already persist in Home Assistant configuration entries. The missing behavior was recovery classification: a reboot could return a session-related 403, an unavailable login endpoint, or reject a newly issued session while still starting. Earlier code could turn these temporary states into ConfigEntryAuthFailed, stopping automatic coordinator polling and requesting user input.

- Probe the session endpoint for API 403 responses. Renew rejected sessions once per operation with the saved credentials, keeping the selected project/site. Treat a genuine operation permission failure as a query error without a login loop.
- Keep temporary login HTTP failures, missing sessions, unavailable attestation, malformed bootstrap challenges and repeated session rejection retryable through normal HA polling/setup retries. Discard invalid/stale cookies, bearer tokens and attestation keys before the next login.
- After transport loss, invalidate the in-memory session and log in again on the next poll. Do not immediately replay ambiguous transport failures or control writes.
- Still require manual correction when the login endpoint actually rejects the credentials. Reject invalid SCRAM server proofs. Existing cookie-only entries must provide username/password once through Reconfigure for recovery after token loss.
- Credentials remain in Home Assistant configuration storage; session material remains in memory. No credential values are logged, exported in these notes, or sent to a third-party service.

Validation: 140 Python tests, including simulated controller restart with 403, login/attestation unavailability followed by recovery, transport interruption, repeated expiry recovery, concurrent renewal, a fresh client using persisted credentials, coordinator retry versus hard authentication failure, and no replay of failed writes. Existing Chromium/WebKit checks cover the unchanged curve module. Physical controller power interruption is not performed by these automated tests.

Update through HACS and restart Home Assistant. Existing username/password entries need no credential change. If the entry uses only a captured cookie, choose its menu → Reconfigure and enter the controller credentials once. The integration then renews sessions automatically when the controller is reachable and its login service is ready. Entities remain unavailable during an outage; missed measurements and physical actions are not recreated.
