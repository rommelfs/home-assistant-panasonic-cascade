# v0.12.0 — Optional heat-pump priority with battery charging reserve

Allow PV buffer charging to start while the inverter is still charging the battery and exports little to the grid. Enable **Heat-pump priority** in the PV options and configure the battery reserve, default **1,000 W**. The option defaults to off, preserving existing export-only installations and their source/sign mappings.

Available surplus equals signed grid export plus battery charging, capped by measured PV production, minus the battery reserve. Start/stop thresholds (default 1,500/500 W) apply after this reserve; stable-start timing remains mandatory. Battery discharge above 100 W, stale/invalid measurements, temperature, heating-mode and lease protections remain active. A small discharge is deducted from the budget rather than treated as PV.

Grid fluctuations near zero can use a priority-only configurable 0–100 W tolerance, default 50 W. Import beyond that limit blocks/stops charging. Export-only mode still rejects all import. Dashboard/status now show available surplus and battery reserve.

This is a reactive offset permission, **not compressor power regulation**: it cannot guarantee an exact minimum battery charge rate or eliminate brief import/discharge transients. Restoration removes only the offset owned by this integration; ordinary heating may continue. No inverter/battery limits or operating modes are modified.

Update in HACS, restart HA, open **Configure → PV buffer charging**, enable priority and set the desired battery reserve. Keep the verified sources/signs; normal operation still requires the actual buffer temperature. Existing temperature-free test restrictions remain in force.

Validation: **199 Python tests**, including a real local HA automatic priority start/service/restore test with simulated controller and sensors; five frontend logic tests. No live heat-pump command was issued during development.
